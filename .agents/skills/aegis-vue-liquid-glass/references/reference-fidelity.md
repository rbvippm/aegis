# 冰川蓝 2.0 参考图还原细则

## 参考区域与尺寸解释

批准资产：`../assets/aegis-approved-home.png`，与用户指定的 `04-glacier-liquid-glass-ai-home.png` 对照查看。画面是 1536×1024 的双设备展示海报，不能把整张图宽高当作应用 viewport。

- 左侧 H5 可见应用区域大致在 x358–733、y177–926；右侧 Telegram 应用区域大致在 x805–1176、y179–926。坐标只用于识别区域，不是生产 CSS 坐标。
- 先排除设备框、状态栏、地址栏、TG 原生标题栏、海报标题、左右说明栏及底部三条说明。H5 与 TG 的内容起点按实际宿主安全区计算，不能保留被排除区域的空白高度。
- 以下尺寸是以约 390px 应用宽度推导的实现起点，允许为可读性和实际内容微调；不是从生成图精确测量的官方参数。
- 默认桌面也展示居中约 390–480px 应用栏；用户未要求桌面站时，不自动扩成 900–1100px dashboard。避免在 641px 一跨断点就出现宽屏营销布局。

## H5 首页分区

| 区域 | 应呈现的细节 | 建议起点 |
| --- | --- | --- |
| 品牌头部 | 左侧 AE 盾形品牌与深蓝 Aegis，右侧语言/菜单按现有功能提供；下面整行三段角色切换 | 品牌行约 44px；角色条约 30–34px；总区高约 80–90px |
| 角色切换 | 用户/代理/平台等宽；底轨浅蓝；选中为鲜蓝玻璃胶囊与白字 | 左右与内容对齐；不得挤在两行主标题右侧 |
| 介绍区 | 单行“看清平台，再做选择”风格标题、短蓝色副标题，右侧局部冰晶盾牌、底部低对比冰川 | 高约 105–120px；标题 24–26px；不要加英文 eyebrow 和多段营销文案 |
| AI 卡片 | 左上圆形星芒球、右侧紧凑标题及副标题；下方完整输入框和独立浅蓝建议行 | 卡片约 170–190px；内距 12–14px；标题 20–22px，不做两行超大 hero |
| 四个快捷入口 | 一行四等分，蓝柱形/紫天平/金皇冠/绿用户组；每格一个图标和短标签 | 高约 70–78px；间距 8px；不加大段描述和装饰箭头 |
| 监测摘要 | 标题与链筛选；左侧耗时与绿色趋势，右侧细蓝折线和浅渐变面积 | 高约 120–135px；主数 28–32px；不额外插入大面积空白 |

在约 390×780–844 的可用 viewport，目标是首屏依次看见品牌/角色、介绍、AI 卡、四入口、监测摘要以及平台行的起始部分。实际可见内容随安全区和字体变化，不通过缩小全页、隐藏必要状态或覆盖列表伪造首屏密度。不能让 AI hero 单独占去约半屏。

## Telegram 入口态

右侧图从应用自己的品牌行开始：Aegis AI 与连接/演示状态 → 一行问题标题和短说明 → 独立输入框 → 三个工具胶囊 → 赛事卡 → 两个监测统计 → 出金动态 → 同材质底栏。赛事卡的时间居中，两队标识分居两侧，下方整行蓝色 CTA。

只在用户任务需要时采用此布局。长分析对话仍按分析契约展开。截图中的绿色“内部知识库已连接”不是产品事实，不得为了视觉还原伪造连接状态；未接入时按当前产品文案呈现，不默认重复添加演示标记。

## 材质与颜色的实际差异

- 蓝色焦点要鲜明：保留 #2563EB 品牌基色，局部高光可用 #168BFF/#60A5FA，深色文字可用 #081C50 一类藏蓝。避免全页面灰蓝、低饱和、模糊到没有焦点。
- 玻璃至少分出外部浅蓝细边、内部白色亮沿、浅色透明体、下缘冷蓝阴影。可从 `border: 1px solid rgba(255,255,255,.9)`、内高光与柔和蓝色投影开始，再对照截图调节。不要靠粗白框或强外发光实现全部层次。
- 输入框是圆角长条，白底向冰蓝渐变，外围有薄双层边缘和短阴影；发送是 36–42px 的蓝色圆按钮、白色斜向发送箭头。点击区可通过容器达到至少 44px。不要把空输入的 disabled 状态做成几乎看不见的圆点。
- 主 CTA 与选中胶囊有上缘亮带、中心鲜蓝和下缘浅青反光；纯实色只用于减少透明度/不支持特性的降级。
- 中央 AI 为圆球轮廓，内部四角星芒与小号 AI，白色双环与柔和蓝影；球上凸且不改变另外四项的等距位置。常驻突出与路由选中是两件事，只有当前页带 aria-current。
- 数据卡接近实色乳白，控制层才使用背景模糊。玻璃透明度不能导致背后的行文字透叠、阅读模糊。
- 保留低对比冰川/冰晶作为标题区局部视觉锚点。没有独立资产时，用可维护的 SVG/CSS 做简化晶面并注明近似；不可直接拿整张海报当背景、把字栅格化，也不能把通用描边盾牌当作冰晶资产已完成。

## 图标、字体、密度

品牌 AE 盾牌、英雄区冰晶盾牌、AI 星芒球各有职责。普通工具使用一致的 SVG 家族和线宽；参考图的彩色工具图标可用局部填充、渐变、浅阴影实现层次，不靠 emoji。无独立品牌文件时应诚实说明近似，不擅自宣称官方 logo。

主标题藏蓝且较紧凑，重要数字用等宽数字。正文 14–16px，辅助 12–13px，导航标签 11–12px。禁止当前实现中以 8–10px 中文容纳说明的做法；先删除重复文案，再调模块间距。图中生成文字的错误、真实球队标识、商家数值均不自动成为需要复制的内容。

首页以 8–12px 卡片间距和 12–16px 内距为起点；圆角通常 16–22px，输入/底栏单独使用大圆角。不要所有容器都套同一张 20px 白卡，也不要到处添加 NEW、英文标签和宣传标语。

## 必须做的视觉验收

1. 先查看实际使用的样式覆盖顺序：token、全局 CSS、组件样式与 media query。不能只改模板 token，而实际页面仍被 base.css 覆盖。
2. 截取 390px 首页，与参考图对应应用区域并排比较；另查 360/430px 与一个桌面宽度。不要把整张海报与完整网页直接做像素 diff。
3. 按顺序检查：应用栏宽度/角色条位置 → 介绍与 AI 卡高度 → 四入口/监测在首屏的位置 → 底栏圆球轮廓 → 冰川锚点/玻璃层次 → 字号、图标与数字对齐。
4. 问题应写成具体可操作差异，例如“角色条应独占一行，现挤在标题右侧”“AI 卡高度过大”“中央 AI 是胶囊，应为上凸圆球”。不以“更高级”“增加玻璃感”代替修复要求。
5. 页面修复后重新截图同样的 viewport；检查底栏不遮挡最后一项、输入文字不与发送按钮重叠、安全区和键盘不覆盖操作。减少透明度模式仍应保留形状与层级。
6. 功能检查与视觉检查分别报告。没有实际移动截图，就不能声称完成移动端还原；没有独立晶体资产，就不能声称与 3D 渲染像素一致。
