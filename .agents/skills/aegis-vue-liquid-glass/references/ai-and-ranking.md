# AI 分析与排名

## 一次回答的结构

1. 确认赛事 ID、参赛双方、开赛时刻与时区；“今天/今晚”按用户时区解释，多场匹配需让用户选择。
2. 给出状态、伤停、体能/赛程、盘口变动等有来源的维度。缺失维度显示缺失。
3. 盘口结论带市场、选项、盘口线、支持度、关键不确定性。支持度是解释强度，未经校准不得写成预测胜率。
4. 返回同赛事/同市场/同选项/同盘口线/同结算规则的商家赔率排名。
5. 独立返回已知出入金排名与数据覆盖说明。
6. 附来源、更新时间、快照 ID，允许用户继续追问与查看依据。

UI 不让模型自由拼一大段 HTML。建议后端发送结构化终态结果，前端按卡片渲染；叙述文字可以流式输出，但结构未完整校验前不展示确定排名。

## 赔率口径

- 统一十进制展示，源数据为香港盘/马来盘等时由后端可靠转换，同时保留原始格式与转换记录。
- 同一赛事、market、selection、line、period、settlementRuleId 才可比较；全场与半场、滚球与赛前不可混排。
- 排序按有效十进制赔率降序；相同值并列。已封盘、过期、地区不可用或条款不兼容的报价剔除或另行展示原因。
- 展示抓取时间、可用限额与已知费用/限制；不把需额外满足条件的奖励赔率当成普通可得赔率。
- 无有效报价时显示暂无数据，不生成“最佳商家”。

## 出入金口径

- 分别存入金与出金的统计、链、资产、金额档、观察窗口、来源与样本量。
- 原 PDF 的金额档为小额 <1000U、大额 >=1000U；U 必须映射具体资产及精度。跨币种换算需要明确汇率快照；不把资产符号作为等价证明。
- 时间字段使用秒；演示默认排名为出金中位耗时升序。若选择 P95、成功率等另一个指标，标题和口径随之改变。
- 链上观察的转账确认耗时不能冒充平台从申请到到账的耗时；缺少申请时刻时写明测量起止点。
- 不同测量起止点不能混排。没有完整发起/失败记录时，不推导出金成功率。
- 只有同链、同资产、同金额档、同窗口、同测量方法且达到配置样本门槛的行参与排名；门槛由后端返回，前端不硬编码一个“行业标准”。
- 缺失、过期、样本不足行展示原因但不分配排名；数据不足不写成商家异常或零到账。
- 来源通常有覆盖偏差，显示“已知数据”；出金快慢不等同于偿付或安全保证。

## 来源与实时性

每条关键事实/结论引用 sourceIds，可展开查看来源名称、类型、事件时间/抓取时间和引用摘录。内部知识库只输出用户有权访问的摘录或安全来源标签，不暴露内部地址与完整文档。

响应包含 demo 标记、asOf、freshness、snapshotId。异步结果不可把旧问题的排名附到新问题；使用 requestId/conversationId 关联。前端当前时间不能冒充数据更新时间。

## 请求与事件建议

`POST /api/ai/analyses` 提交 message、timezone、locale、conversationId 和可选 fixtureId。流式场景可用 fetch + ReadableStream，定义事件 status、text_delta、result、error、done；也可用 SSE 连接令牌，但不能把长期密钥放 URL。

将这些视为待与后端确认的建议契约，不宣称已有接口。停止用 AbortController；重试避免重复生成消息；断流展示部分结果和继续操作。协议按 requestId 与递增序列防止重复应用事件。

`../assets/aegis-contracts.ts` 是可复制的类型草案，需与后端 schema 对齐并加运行时校验，不是现成排名引擎。
