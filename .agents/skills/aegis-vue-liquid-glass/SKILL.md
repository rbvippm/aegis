# Aegis 冰川蓝液态玻璃

将批准的视觉风格落实为可维护的 Vue 页面。默认简体中文、浅色背景、移动端优先；保留用户明确指定的技术选型与已有代码习惯。

## 当前已确认阶段

先读 [当前实现基准](references/current-baseline.md)，查看其中列出的首页与占位截图。当前仅首页保留完整界面；其他导航页与二级页保持文案占位，用户指定哪个页面再逐页设计。不要因为历史功能契约或概念图而自动恢复其他页面。

Codex 与 Cursor 共用本技能；`.cursor/rules/aegis.mdc` 只是入口，不维护第二套规范。当前实现基准记录已确认的字体、过渡、底栏和页面范围；概念图细则用于方向，不覆盖后续已确认的实现与用户新要求。

## 先确定边界

- 先读项目现有 AGENTS.md、package.json、锁文件与相关页面，沿用现有包管理器；新项目默认 Vue 3 + Vite + TypeScript + Vue Router + Pinia。
- 新建或调整视觉先读 [视觉规范](references/design-system.md) 与 [参考图还原细则](references/reference-fidelity.md)，查看 `assets/aegis-approved-home.png`；不能只读取颜色 token 就开始实现。图片是构图和材质参考，不把图里的演示数据、错字或装饰文案当成产品事实。
- 组织新模块时读 [项目架构](references/architecture.md)；修改 AI、赔率或资金排名时读 [AI 与排名契约](references/ai-and-ranking.md)。只读当前任务需要的参考。

## 不应漂移的设计

- 主色 #2563EB，辅助 #60A5FA，背景 #F5F8FF，表面 #FFFFFF，正文 #14213D。优先复用仓库现有 token 与 `reference-home.css`；`assets/aegis-tokens.css` 仅为早期基础模板，不覆盖当前实现基准。
- 液态玻璃集中在悬浮导航、胶囊按钮、搜索/聊天输入框、少量浮层。包含半透明底、边缘高光、有限模糊和层次阴影；长表格、分析正文使用接近实色的浅底。
- 这是 H5/WebView 中对 iOS 26 Liquid Glass 的视觉近似；CSS 不是苹果原生材质。不要承诺原生实时折射，也不要把产品限定为 iOS 26，兼顾 Android TG 与普通浏览器。
- 保持清晰信息层级和中文阅读密度。不要把效果图中的手机外框、Safari 地址栏、TG 原生标题栏、方案标题或手机外的雪山布景复制成产品界面。手机内标题区的低对比冰川/冰晶装饰属于视觉语言，可局部使用，不能因此删成纯色空白。
- 底部导航为 首页 / 监测 / AI / 对比 / 我的，AI 入口常驻且突出；只有当前路由标为选中。首页同时提供直接提问输入框。
- 不因视觉改动额外添加下注、自动交易、钱包连接、推广跳转或新业务。VIP 与代理入口按当前任务范围实现。

## 参考图还原优先级

- 参考图内的应用区域是构图依据，外部海报不是页面。先锁定移动栏宽度、首屏模块位置、紧凑密度和蓝色焦点，再调整材质。不得将其自由改写为大留白营销落地页。
- 默认沿用左侧 H5 首页结构；右侧图是 Telegram 首页入口态，不是长分析详情的截图。两者共享材质和导航，不把两套模块随意叠加。
- 玻璃要能看见白色内沿、浅蓝外沿、局部亮斑和下缘阴影；单独添加 blur 或统一半透明白卡不能视为还原完成。中央 AI 是凸起圆形蓝色玻璃入口，不是横向蓝胶囊。
- 参考图中的 logo、AI 星芒球、冰晶盾牌是不同视觉角色；不得全都替换成通用线框 ShieldCheck。优先复用已批准独立资产；只有整张海报时不得裁出含文字和设备的区域充当背景或功能组件。

## 当前文案与抽屉约定

- 不因新增功能默认添加“演示数据”“演示体验”等重复文案。数据模式通过配置与 adapter 明确，API 失败不可静默回退 mock，未接入服务不可伪造已连接状态。
- 通用抽屉最高为当前可视屏幕的 80%，拖动和停靠均限制在此范围；支持上拉最高、慢拉半收起、快拉/长拉关闭。手机默认不让把手出现自动焦点蓝框，键盘操作仍保留焦点提示。

## 实现顺序

1. 将页面拆为平台外壳、玻璃基础组件、业务组件；先复用再扩展。本项目按当前实现基准逐页设计，未指定的路由继续占位。
2. 把静态视觉、业务数据和平台调用分开。服务层提供 DTO；组件不内嵌请求、排名算法或模型提示词。
3. 对用户此次指定实现的业务页，再按需实现 loading、empty、error、stale 和 partial 状态；数据缺失用“暂无数据”，不填 0 或伪造实时值。
4. 用户后续要求实现 AI 业务时，回答使用可校验的结构化卡片，支持停止、重试和继续追问。真实模式由后端查询数据并计算排名，模型负责基于来源解释；原型使用独立 mock adapter；不默认给每个功能添加“演示数据”“演示体验”等文案，按用户指定文案呈现，技术数据模式在配置中明确。
5. 检查 360/390/430px 宽度、键盘弹出、安全区、长中文、弱网错误和无模糊降级；运行项目已有类型检查、构建及与本次改动相关的测试。
6. 按还原细则对照同尺寸实际页面截图，先修正结构与首屏密度，再检查材质、图标、文字和安全区。仅通过类型检查、测试和构建不等于视觉通过；未截图时明确未做视觉验证，不宣称像素一致。

## 双端与 AI 的关键约束

- Telegram SDK 只通过平台 adapter 使用；普通 H5 不因缺少 TG 环境崩溃。检测宿主后按当前 SDK 文档初始化并释放事件监听，不通过 UA 猜测能力。
- 正式应用不模拟 Telegram 登录；initData 由后端验签和时效检查。Bot token、模型密钥、完整内部知识库不进入前端或 VITE_* 变量。
- AI 必须先确认赛事、市场、盘口和时间；结论之后附同盘口商家赔率排名与已知出入金数据排名。显示来源、快照时间、链、金额范围、观察窗口与样本量。
- “最优赔率”与“出金更快”是两套排序；监测耗时不等同于商家安全评级。缺失、过期、样本不足的数据不参与相应排名。
