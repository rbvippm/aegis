# 个人中心

2026-10-24 按用户确认的四屏方案落到 `/me`，保留已有 `/me?section=vip`、`/me?section=agents` 服务页面及首页入口。主页、收益与绑定、工单、账户抽屉沿用冰川蓝、AE 品牌、共享底栏与 BottomDrawer。

## 确认后的取舍

- 移除福利码、公开展示活动、评价公开、减少透明度、数据与账户注销入口；不更改其他页面已有的减少透明度降级能力。
- 新增意见反馈与关于我们，主页和账户抽屉均可进入。
- 收益为记录，由平台／人工站外结算；不保管资金，不提供充值、领取或提现。
- UID 绑定与奖励资格分开；新绑定或修改 UID 后资格回到待验证，不因客户端保存而自动通过。
- 私密工单与证据不公开。当前只保存本地草稿，不发起真实投诉或外部通知。
- 邀请、VIP／AI 权益与代理入口保留；个人中心不虚构会员套餐、AI 额度、返佣层级或价格。

## 页面和交互

`/me`：示例身份、收益摘要、绑定平台／关注／AI记录／工单四入口、邀请和代理，以及账户、客服、反馈和关于入口。

`/me?section=earnings`：绑定平台与收益明细切换。`tab=records` 可直接进入结算明细。金额使用整数分累计；待核对不混入已结算。平台 A/B 为已绑定样例，C 未绑定。字段校验后的 UID 只在当前标签页保存，验证服务未接入。

`/me?section=tickets`：全部／处理中／已结束、进度时间线、新建与补充草稿。描述和金额校验；证据最多5个，单个10MB内，支持 PNG/JPEG/WebP/PDF。仅保留文件名、大小、类型元数据，不读取或上传内容。提交按钮明确为保存草稿；补充资料不改变原样例的处理状态。

`/me?section=messages`：平台／工单／系统消息过滤和本地已读状态。通知内容与 Telegram／邮箱渠道偏好仅存当前会话，不实际发送。

`/me?section=follows`：读取并校验体育对比页的本机关注 ID，取消会同步回同一存储；平台关注为本页会话偏好。没有关注时显示空状态。

`/me?section=history`：展示 AI 模块真实的当前标签页会话，点击恢复，不新造对话记录。

账户抽屉：资料、登录说明、设备未接入状态、通知、语言、反馈、关于、退出预览。仅有简体中文，不假装切换未实现的语言。Telegram 与邮箱只说明真实身份服务待接入；邮箱只校验格式，不发验证码或模拟登录。退出预览清空个人中心输入草稿，切为游客，不影响真实账户。

## 服务和隐私边界

`features/profile/` 按 types、纯校验与汇总 logic、Pinia会话 store、页面与抽屉组织；固定假平台和记录在 `src/mocks/profile.ts`。

仅 `demo` 模式加载示例身份、收益和工单。`api` 模式无示例数据，拒绝保存模拟业务。绑定、工单、反馈与通知未接入真实服务；无请求、无上传、无真实认证和资金操作。身份、UID、草稿与证据元数据不写入本地持久存储，刷新即清除。体育关注复用现有非敏感本机偏好。

## 验证

单元测试覆盖整数分汇总、UID 改动不授予资格、草稿状态、金额与文件拒绝规则、游客限制和 API 模式不回退。移动端覆盖主页入口、删除项、新增反馈／关于、绑定、工单、消息、游客、关注与 AI 记录联动，以及360/390/430px无溢出、底栏留白和抽屉。截图保存在忽略目录 `outputs/profile-implementation/`。真实 iOS/TG 登录与系统键盘仍需实机验收。
