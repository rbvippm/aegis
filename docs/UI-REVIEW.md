# UI 双轮走查与修复规范

Codex 与 Cursor 共用。适用于每次页面、组件、功能、文案或交互变更。遵循 Aegis 共享设计技能和用户最近确认的界面；已有测试通过或生产打包成功不能替代实际 UI 走查。

## 每次完成前必须执行

1. **确定范围**：读取已有差异，列出本次影响的主页面、二级页面、弹框、通用组件及状态。保留其他工具的工作，功能范围以用户最新指令为准。
2. **第一轮检查与修复**：实际运行应用，按从上到下、从左到右检查首屏、中段、页尾；打开受影响的弹框、下拉和详情。保存截图，读取实际计算样式，记录具体问题并修复。
3. **第二轮独立复查与修复**：第一轮修改完成后，在相同尺寸、相同数据和相同交互状态重新截图，实际查看修复后的截图。重新检查整页及关联组件，不能只看原问题所在位置；发现问题继续修复，并再次复查受影响的视图。
4. **工程验证**：运行适用的类型、lint、单元测试、移动端交互测试和本地生产打包。验证样式覆盖、路由切换和共享组件回归。禁止把截图生成成功或自动测试通过当成视觉验收通过。
5. **交付记录**：报告走查范围、发现并修复的问题、复查结果与未实测环境。提供截图或走查记录路径。没有完成第二轮时，不得宣称 UI 验收完成。

## 统一检查标准

| 维度       | 标准                                                                                                                                                                                                         |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 字体       | 系统字体栈；正文14–16px，操作与标签12–14px，辅助说明至少12px，区块标题17px左右；页面标题按批准基准24–28px。10–11px仅用于极次要时间元信息及已批准底栏标签，不用于盘口、平台分、表格规则、权益说明或操作入口。 |
| 字重与数字 | 正文400，标签500，平台名600，标题650–700；不把整页中文加粗。金额、赔率、时间使用 tabular-nums。                                                                                                              |
| 配色       | 复用 `tokens.css`：正文 `--ae-text`，次级 `--ae-muted`，高光 `--ae-highlight`，选中胶囊与主按钮 `--ae-pill`。禁止再写中间压深的另一套蓝；订阅等级色除外。普通小字在浅底上目标对比度至少4.5:1。涨绿跌红，并有箭头或文字。 |
| 层级与材质 | 控制层使用玻璃胶囊、薄边与高光；正文及表格使用接近实色的浅底。选中、未选中、禁用、锁盘和封盘有明确区别；检查原生样式重置与媒体查询是否覆盖选中态。                                                           |
| 间距与对齐 | 主内容左右12px，卡片内距12–16px，区块间8–12px为起点；逐行检查左右边缘、图标基线、数字列和多行文本。不得通过缩小正文解决拥挤。                                                                                |
| 触控与焦点 | 交互目标原则上至少44×44px。小图标保留原视觉尺寸并扩大可点击容器；键盘 focus-visible 清楚，手机点击不留下错误焦点框；下拉统一 GlassSelect。                                                                   |
| 抽屉       | 只保留一个主标题，最高不超过当前可视屏幕80%；上拉、慢拉半收起、快拉/长拉关闭均复查。长内容可滚动，底部操作可完整露出。                                                                                       |
| 横向与底部 | 页面不能左右跑；宽表只在自身容器横向滚动。页尾内容与最后一个操作不能被底栏、悬浮条或安全区遮挡。                                                                                                             |
| 动效与降级 | 150–180ms轻量反馈，遵守减少动效；截图避开过渡中间帧。减少透明度或无 blur 时保留浅底、边线和清晰文字。                                                                                                        |
| 数据与业务 | 使用本轮既定 mock，不伪造真实连接。视觉修复不能删除已确认功能、改收益口径或自动恢复旧页面。                                                                                                                  |

## 必测尺寸和状态

- 390px 是主截图基准；360px、430px检查窄屏与宽屏，一个桌面尺寸检查居中最大430px应用栏。
- 每个受影响页面检查首屏、中段、页尾；关键二级页和弹框也在范围内。
- 切换全部受影响 tab、下拉选项、选中/禁用态、长平台名、多行中文、空状态、缺失报价、锁盘/封盘。
- 输入时检查文本与按钮不重叠；宿主键盘、Safari、Telegram 只有实际可用并实测时才报告通过。Chromium 的移动视口不能称为真机测试。
- 使用可重复的数据和视口保存 `outputs/ui-audit/<轮次>/` 截图；该目录是本地验收产物，不自动上传原始资料或提交输出文件。

## 主导航切换稳定性

首页、监测、AI、对比、我的主导航内容与外壳必须在同一次更新中同步切换。不使用整页 `out-in` 先淡出、再淡入的方式，使旧页面继承目标页头部、padding或滚动布局；保留按钮自身的轻量反馈即可。动效走查须使用正常动效设置检查切换中的连续帧，并覆盖冷进入、快速连点、已滚动页切换和浏览器返回，不能只用减少动效模式或切换后的静态截图验收。
