# 省流工作流程

Codex 与 Cursor 共用，适用于通过手机热点开发 Aegis。按用户最新要求执行；本规范只调整工作流程，不修改模型、网络或系统设置。

## 日常修改

1. 先看现有差异，按任务读取相关文件和片段；已读且未变化的规则、参考图不反复读取。不默认全仓输出源码、日志或目录。
2. 合并独立查询，保留有依赖的操作顺序；短命令给足合理等待时间，不频繁轮询。只汇报有意义的进展。
3. 仅做与改动相关的本地定向验证。日常不自动运行 `npm run check`、`npm run build`，不通过其他命令变相执行同样的全量流程。纯文档/规范修改只检查差异、链接和一致性。
4. UI 修改按 `UI-REVIEW.md` 完成一轮走查，直接对照设计规范，通过实际页面交互、DOM、计算样式和布局尺寸检查。默认不截图、不做截图对比、不保存或回传走查图片；发现问题后只复核对应修复。
5. 只回传退出码、测试摘要及必要错误片段，不打印完整成功日志、大段无关源码或图片编码，不默认将日志保存成文件。确需排障的临时日志按需使用，避免包含密钥或个人敏感信息。
6. 复用已安装依赖和浏览器；不例行安装、更新、下载资源或访问外部网站。任务或事实核验确有需要时才访问，避免重复下载。保持正常依赖与浏览器缓存，不以省流为由跳过必要验证。
7. 在对话中简述修改范围、验证结果和未实测项，不为每次任务新增记录、总结、审计或验收文件。仅修改功能所需文件与已有规范；用户明确要求文档、图片等交付物时再按指定范围生成。

## 提交或推送 GitHub

仅在用户要求提交/推送 GitHub 时，按 `PUSHING.md` 先运行 `npm run check`，再运行 `npm run build`；失败先修复，通过后才提交/推送。仅回传检查结果和必要错误，不默认保存完整输出文件。不得自动提交、推送或部署。

## 流量判断

本地开发服务器、构建、测试及保存截图主要在本机执行；返回模型的文本、图片与外部资源访问会产生网络传输。定向验证可减少耗时及日志回传，但不能把减少本地构建次数直接等同于节省了相同数量的网络流量。模型用量、token 与热点流量并非同一指标，不承诺未经测量的节流比例。

如需量化，后续可由用户记录相同任务前后的热点总流量，并结合进程网络统计比较。未经单独授权，不安装监控工具、不抓包、不修改网络设置。
