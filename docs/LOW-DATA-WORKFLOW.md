# 省流工作流程

Codex 与 Cursor 共用，适用于通过手机热点开发 Aegis。按用户最新要求执行；本规范只调整工作流程，不修改模型、网络或系统设置。

## 日常修改

- 优先一次定位、集中修改、一次必要验证；独立查询合并，依赖操作保持顺序，失败再追加排查。不为满足次数凑检查。
- 定位先用 `rg -l` / `rg -n`，再读取命中位置附近片段。默认只回传约 500–1000 字以内的相关输出，超出时在本地筛选后返回摘要；不能截掉必须处理的错误。规则、参考和文件只有首次需要或发生变化时才重新读取。
- 默认不截屏、不读取整页浏览器快照、不生成图片、HTML 报告、视频、追踪包或任务记录；用户要求交付文件时才生成。UI 对照规范检查受影响区域一轮，未实测必须如实说明。
- 样式、间距、图标、文案等小改动不新增测试、不默认执行测试套件；核对相关模板、样式与差异即可。业务逻辑或共享交互按影响选最小必要回归，成功后停止重复验证。日常不运行 `npm run check` / `npm run build`，不以其他命令变相执行全量流程。
- 进展只说发现、阻碍与结果；最终回复以几句话说明结果和重要限制，不重复过程、代码、历史记录或大段成功日志。完整日志不默认落盘。
- 不默认联网检索、安装/更新依赖、下载浏览器、访问竞品或生成图片。优先复用本地资源与缓存；任务或核验确需联网时只访问必要内容。浏览器缺失不反复尝试不同路径或自动安装。
- 不自动打开新会话或调整模型、推理设置、系统网络。跨独立任务且历史很长时，建议用户在同一项目新开会话；不要为迁移再生成长篇记录文件。

## 自动化产物

端到端测试默认仅输出简短终端结果，关闭 HTML 报告、截图、视频与失败追踪。仅用户明确要求截图/调试产物时，才用 `AEGIS_CAPTURE_UI=1` 按需开启已有截图语句和追踪；不默认开启。实际页面截图与输出文件均不自动提交。

## 提交或推送 GitHub

仅在用户要求提交/推送 GitHub 时，按 `PUSHING.md` 先运行 `npm run check`，再运行 `npm run build`；失败先修复，通过后才提交/推送。仅回传检查结果和必要错误，不默认保存完整输出文件。不得自动提交、推送或部署。

## 流量判断

本地开发服务器、构建、测试及保存截图主要在本机执行；返回模型的文本、图片与外部资源访问会产生网络传输。定向验证可减少耗时及日志回传，但不能把减少本地构建次数直接等同于节省了相同数量的网络流量。模型用量、token 与热点流量并非同一指标，不承诺未经测量的节流比例。

如需量化，后续可由用户记录相同任务前后的热点总流量，并结合进程网络统计比较。未经单独授权，不安装监控工具、不抓包、不修改网络设置。
