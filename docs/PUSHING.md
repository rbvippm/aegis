# GitHub 提交与推送规范

Codex 与 Cursor 共用本规范。用户授权提交或推送时，每次执行；它不授权日常开发自动提交、推送或部署。

## 执行顺序

1. 查看 `git status`、差异、当前分支和 `origin` 地址，保留另一工具的工作，确定本次提交范围。检查忽略规则，避免上传密钥、旧业务资料、node_modules、dist 和临时截图。
2. 完成全部拟提交修改后，先执行项目检查 `npm run check`，再执行生产打包 `npm run build`，确认退出码为 0。只运行开发服务器、旧的成功记录或远程 CI 不能代替本次本地打包。
3. 任一检查或打包失败时，先定位并修复，再重跑相关检查和 `npm run build`。通过之前不得创建本次提交，不得推送到 origin；不能通过关闭校验、跳过错误或提交产物绕过失败。确实需要用户信息才能修复时，保留修改并说明阻塞。
4. 打包通过后核对暂存差异，执行 `git diff --cached --check`，仅提交本次授权范围的文件。打包后若修改了源码、配置或依赖，必须重新打包通过，再提交。
5. 在用户指定分支上创建提交并推送至已核对的 origin；不默认强制推送，不覆盖远程历史。若远程有新提交，先安全整合；产生新代码树后重新检查和打包通过，再提交或重试推送。
6. 推送后核对远程分支 SHA 与本地提交一致，报告分支、提交号和打包结果。未成功推送时明确说明，不将“本地已提交”称为“已上传”。

`npm run check` 当前包含类型检查、lint、单元测试和 Vite 构建；`npm run build` 是项目声明的生产打包命令（含类型检查）。涉及路由或交互时，按改动范围额外运行相关端到端测试。测试和打包产物保持在 .gitignore 中。
